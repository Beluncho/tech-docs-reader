# Промпты LLM-ассистента маппинга (этап 4)

Промпты для предложения маппинга таблиц через LLM. Загружаются бекендом
(`app/llm_mapping.py`) и рендерятся подстановкой плейсхолдеров.

## Состав

| Файл | Назначение |
|---|---|
| `system.txt` | Системный промпт: контракт входного формата, 7 ролей, правила координат, JSON-схема ответа |
| `matrix_table.txt` | User-шаблон: матрицы модель×параметр (обе ориентации) |
| `keyvalue_table.txt` | User-шаблон: таблицы «метка → значение» |
| `complex_table.txt` | User-шаблон: многоуровневые шапки, повернутый текст, большие merged-блоки |
| `examples/*.txt` | Few-shot примеры на синтетических таблицах (USER + ASSISTANT) |

## Контракт входного формата (фиксирует system.txt)

- Markdown-таблица; первый столбец `#` — номер строки с нуля; колонки пронумерованы `0..N-1`.
- Merged-блок показан текстом в **якоре** (верхняя-левая клетка), продолжения — символ `·`.
- После таблицы — список `Merged cells:` вида `(row, col) rowspan x colspan — «текст»`.
- Длинные тексты ячеек обрезаются (60 симв.; для широких таблиц лимит сжимается до ~24–36,
  бюджет ~720 симв. на строку) — размечать нужно по координатам, не по тексту.
- Большие таблицы (>40 строк) сжаты: голова + хвост (3 строки), середина заменена маркером
  `... (пропущены строки A–B из N: продолжение той же структуры) ...`. Номера строк сквозные;
  скрытые строки LLM размечает range-ами по аналогии с видимыми. В списке merged — только
  якоря из показанных строк.

## Плейсхолдеры user-шаблонов

`{doc_context}`, `{page}`, `{table_meta}`, `{table_markdown}`, `{merged_cells}`, `{context_hint}`

Рендер — простой заменой (`template.replace("{" + name + "}", value)`), НЕ `str.format`:
в шаблонах есть литеральные фигурные скобки (JSON-примеры). `{doc_context}` — имя документа
без расширения + тип (`build_doc_context`); `{context_hint}` — либо пустая строка, либо
строка «Контекст: ключевые слова: …», оканчивающаяся переводом строки.

## Схема ответа LLM

См. конец `system.txt`. Ключевое:

- роли — ровно id ролей Visual Mapper (`frontend/js/visual-mapper/roles.js`):
  `model | param | value | unit | section | condition | ignore`;
- координаты — 0-базовые, по сетке исходной таблицы (до структурных правок пользователя);
  для merged-блока — только якорь;
- `range: [r0, c0, r1, c1]` (включительно) — компактная запись зоны: роль получают все блоки,
  **якорь** которых лежит в прямоугольнике. Разворачивается в по-якорные аннотации при
  валидации ответа. Это главный экономитель токенов: матрица 19×8 размечается
  3-5 аннотациями вместо ~150;
- `label` — нормализованное название (без единиц), `unit` — единица (обычно из названия
  параметра), `group` — категория; `confidence` 0..1, `alternatives` для спорных клеток;
- `notes` — сомнения уровня таблицы.

## Примеры (few-shot)

Формат файла — две секции:

```
=== USER ===
<полный user-промпт, как придёт из пайплайна>
=== ASSISTANT ===
<эталонный JSON-ответ>
```

Все четыре примера синтетические: вымышленные модели и значения, но сохранены реальные
структурные признаки — merged-ячейки, двухстрочные шапки, повернутый текст и координаты.
`scripts/vm-renderer-test/export_table.py` помогает выгрузить структуру любой таблицы
в том же формате.

| Файл | Тип | Чему учит |
|---|---|---|
| `cns_pump.txt` | matrix rows | rowspan-значения на группу моделей, единицы в названиях параметров, заголовок оси без роли |
| `welch_pump.txt` | matrix columns | модели в шапке, отдельная колонка Unit (роль unit), colspan-значения «одинаково для всех» |
| `cm_pump.txt` | complex / matrix rows | двухстрочная шапка, повернутый текст (обратный порядок слов), справочные колонки «в приложении» → condition, пониженная уверенность |
| `oprosny_list.txt` | keyvalue | секции, единицы до/после названия, min/max-паттерн, чек-листы — не размечать |

## Как менять промпты

1. Правь `system.txt` / шаблон / пример, сохраняй кодировку UTF-8.
2. `python -m pytest tests/test_prompts.py -q` — проверяет наличие файлов, плейсхолдеры,
   разбираемость JSON-схемы и всех эталонных ответов; `tests/test_llm_mapping.py` —
   сервисный слой (мок LLM).
3. Точность на закрытом эталонном наборе измеряется отдельным прогоном, который
   в публичную версию не входит. В стенде доступны живые метрики `/api/llm/metrics`.
4. Кэш инвалидируется сам: ключ — sha256 сообщений целиком (таблица + контекст
   + промпты), правка любого файла в этом каталоге меняет ключ.

Важно: few-shot ответы — одновременно эталон для проверки. Правя `examples/*.txt`,
держи разметку согласованной с таблицей: все value-колонки должны быть покрыты.

## Ориентиры

- точность предложений >85%, время <15 с, стоимость <2₽/таблица (~3500 токенов);
- режим JSON (`response_format: json_object`), temperature 0.1, перебор моделей с фолбэками —
  настраивается в `app/llm_mapping.py`, см. существующий контур `app/llm.py`.
