# FAQ и устранение неполадок

Ответы на частые вопросы пользователя стенда. Про установку и запуск —
[README.md](../README.md); про визуальный маппинг — [VISUAL_MAPPER.md](./VISUAL_MAPPER.md);
про LLM-ассистент — [LLM_ASSISTANT.md](./LLM_ASSISTANT.md); про API —
[CONTRACT.md](./CONTRACT.md).

## Частые вопросы

### Какой набор выбрать?

Если набор не подобрался автоматически, начните с назначения документа:

| Что в документе | Набор |
|---|---|
| Паспорт/РЭ насоса, есть таблицы «модели × параметры» (1К, НС, СМ, ЭЦВ…) | `pump_main` — основной алгоритм: все пары + матрицы |
| Паспорт, схема «метка → значение» | `passport_pump_2col` |
| Таблица «показатель / ед. / значение» | `passport_table_header` |
| Сертификат/декларация | `certificate_2col` |
| Опросный лист/ТЗ «№ / наименование / ед. / кол-во» | `tz_table` |
| Строки «Метка: значение» (txt/docx/текстовый PDF) | `keyvalue_generic` |
| «Хочу просто увидеть все пары» | `generic_2col_all` |

Полная таблица с пояснениями — в [README.md](../README.md#стартовые-наборы).
После удачного извлечения нажмите «Сохранить правило из результата» — набор
зафиксирует структуру документа, и следующий такой же подхватится автоматически.

### Что значат статусы в списке документов?

- **готов** (зелёный) — документ разобран, таблицы найдены;
- **ошибка разбора** (красный) — файл повреждён или в неподходящем виде
  (детали в мета-строке после открытия);
- **сканы не распознаны (OCR не настроен)** (жёлтый) — PDF без текстового
  слоя, загруженный с флагом OCR, а воркер не поднят. Извлечение из него
  невозможно, пока не появится OCR.

### Загрузка «зависла» — ничего не происходит?

Скорее всего, не зависла: в зоне загрузки показывается
«⏳ Обработка документа…», а большие PDF (десятки страниц с чертёжной
графикой) обрабатываются несколько секунд — это детекция таблиц
(замеры — [PERFORMANCE.md](./PERFORMANCE.md)). Пока идёт обработка,
повторный drop игнорируется. Если статус ошибки не появился и через минуту —
проверьте, что API жив (`API: ок` в шапке), и посмотрите логи сервера.

### Почему у некоторых параметров LLM нет страницы/цитаты — и они пропали?

Так и задумано: LLM-контур проверяет каждую найденную характеристику цитатой
в документе (`evidence`: страница + фрагмент текста). Параметр без
подтверждённой цитаты отбрасывается — это защита от выдуманных значений.
Если параметр точно есть в документе, а LLM его не подтвердил — извлеките его
детерминированно (набор/маппинг) или разметьте вручную в маппере.

### Что значит «📦 из кэша» у LLM-ассистента?

Предложение маппинга для той же таблицы уже запрашивалось — повторный ответ
берётся из кэша, облако не вызывается (мгновенно и бесплатно). Кэш
автоматически сбрасывается при правке промптов на сервере или смене структуры
таблицы. Подробнее — [LLM_ASSISTANT.md](./LLM_ASSISTANT.md).

### Шаблон маппинга не применился к «такой же» таблице

Шаблон подбирается по структуре: у похожей таблицы должны совпасть число
колонок и шапка (точно, либо сходство ≥ 75%). Если поставщик поменял вёрстку
(добавил колонку, переименовал заголовок) — это уже другая структура: откройте
маппер, поправьте роли и при необходимости сохраните новый шаблон. Индикатор
«📌 шаблон» на рамке таблицы в превью страницы показывает, что подобралось.

### «LLM: выключен» в шапке — как включить?

Задайте ключ YandexGPT на сервере: `YANDEXGPT_API_KEY` (и при необходимости
`YANDEXGPT_FOLDER_ID`) в `.env`, перезапустите API. Без ключа стенд работает
полностью локально — недоступны только кнопки «Извлечь через LLM» и
«🤖 Предложить маппинг». Настройка и выбор моделей — [README.md](../README.md#настройка-llm-yandexgpt).

### Документ — скан. Что делать?

Текст из скана извлекается OCR-воркером (PaddleOCR, docker-профиль `ocr`):
поставьте галочку «распознать сканы» при загрузке. Без воркера такая загрузка
закончится статусом «сканы не распознаны». Текстовые PDF, XLSX, DOCX, CSV, TXT
работают без OCR. Развёртывание и альтернативы — [OCR_PLAN.md](./OCR_PLAN.md).

### Куда сохраняются мои наборы и данные?

Всё локально, в каталоге данных (`data/`): документы — `data/documents/`,
пользовательские наборы — `data/presets/*.json`, статистика LLM —
`data/llm_stats.json` и журнал коррекций `data/llm_feedback.jsonl`. В Docker это
volume `tech-docs-data`; наборы переживают перезапуск. Ничего не отправляется
в облако, кроме фрагментов таблиц в LLM-запросах — и только при заданном ключе.

## Устранение неполадок

| Симптом | Причина | Что делать |
|---|---|---|
| «документ содержит сканы, а OCR не настроен» | PDF без текстового слоя, OCR-воркер не поднят | Поднять профиль `ocr` (`docker compose --profile ocr up -d`) или загрузить текстовую версию; см. [OCR_PLAN.md](./OCR_PLAN.md) |
| «LLM не настроен: укажите ключ YANDEXGPT_API_KEY» | Ключ не задан / сервер не перезапущен | Заполнить `.env`, перезапустить API ([README](../README.md#настройка-llm-yandexgpt)) |
| «LLM не смог обработать запрос…» (502) | Все модели перебора не ответили/таймаут | Повторить позже; проверить список моделей `YANDEXGPT_RULE_MODELS`; разметить вручную — таблица и роли не пострадали |
| «набор не выбран: …» при «Извлечь» | Автоподбор не нашёл набор, в списке пусто | Выбрать набор, «Настроить набор»/«🎨 Визуальный маппинг», или «Извлечь через LLM» |
| Извлечение вернуло 0 параметров | Набор не подходит под структуру документа | Попробовать другой набор (таблица выше), настроить маппинг; результат LLM можно сохранить как набор |
| «файл больше лимита загрузки» | Размер > `MAX_UPLOAD_MB` (по умолчанию 50 МБ) | Уменьшить файл или поднять `MAX_UPLOAD_MB` в `.env` |
| «формат не поддерживается (.…)» | Расширение вне PDF/XLSX/XLS/DOCX/CSV/TXT | Пересохранить документ в поддерживаемом формате |
| «в документе нет таблиц — извлекать нечего» | Текст без табличной структуры | Наборы текстового режима (`keyvalue_generic`) либо LLM-извлечение |
| «таблица не найдена / маппинг для таблицы не создан» | Документ перезагружен, таблицы сместились | Переоткрыть документ, заново открыть маппер |
| «встроенный набор нельзя изменить» | Попытка правки builtin-набора | Создать свой набор кнопкой «Сохранить набор»/«Сохранить правило из результата» |
| Странные значения (мусор) в параметрах | Набор зацепил лишние пары | Сузить список имён в конструкторе («Что извлекать → только перечисленные») или разметить точно в маппере; неудачный прогон не затирает прежний результат |
| Хочу начать с чистого стенда | — | Остановить API и очистить `data/` (в Docker — volume `tech-docs-data`); внимательно: удалятся все документы и пользовательские наборы |

Известные ограничения сведены в раздел «Ограничения (MVP)»
[README.md](../README.md#ограничения-mvp).
