# LLM-ассистент маппинга: руководство пользователя

LLM-ассистент — кнопка **«🤖 Предложить маппинг»** в [Visual Mapper](./VISUAL_MAPPER.md).
LLM анализирует структуру таблицы (паспорта, ТЗ, опросные листы) и размечает роли
ячеек — модель, параметр, значение, единица… — черновиком, который вы проверяете
и правите. Это быстрее ручной разметки сложных таблиц с нуля: матрицы
«модель × параметр», объединённые ячейки, многострочные шапки.

Руководство по самому Visual Mapper (выделение, роли, структурные правки,
шаблоны) — в [VISUAL_MAPPER.md](./VISUAL_MAPPER.md). Здесь — только про LLM-часть:
когда её использовать, как читать предложение, что делать со спорными клетками.

---

## Когда использовать

| Ситуация | Инструмент |
|---|---|
| Похожая таблица уже размечалась | Шаблон маппинга (применится по структуре, бесплатно) |
| Таблица новая и сложная (матрица, merged, нестандартная шапка) | **🤖 LLM-ассистент** |
| Таблица простая (2–3 колонки «метка → значение») | Разметить вручную — быстрее, чем ждать ~10 сек |
| Извлечь параметры из одного документа без настройки | «Извлечь через LLM» в основном окне (другой контур, без разметки) |

Цепочка типовой работы: **🤖 предложил → вы поправили 2–3 клетки → 💾 сохранили
шаблон** → похожие таблицы в других документах размечаются автоматически,
LLM для них больше не нужен.

## Что нужно для работы

- **Ключ API на сервере** (`YANDEXGPT_API_KEY` в `.env`). Без ключа кнопка
  неактивна с подсказкой «LLM не настроен». Без ключа в облако не уходит ничего —
  стенд полностью детерминирован.
- **Таблица без структурных правок.** Координаты предложения считаются по исходной
  сетке таблицы: если вы уже объединяли/транспонировали/удаляли строки — кнопка
  заблокирована. Предложите маппинг до правок или верните структуру (Ctrl+Z).

## Как это работает

1. Откройте таблицу в Visual Mapper и нажмите **🤖 Предложить маппинг**
   (секция «LLM-ассистент» под кнопками ролей).
2. ~10 секунд: сервер формирует промпт (таблица + один обучающий пример того же
   типа + контракт формата), вызывает LLM, проверяет и нормализует ответ
   (координаты сверяются с реальной сеткой, зоны разворачиваются в клетки).
3. Предложение **применяется сразу** и заменяет текущие роли. Если у вас уже была
   разметка — появится подтверждение. Откат целиком — **Ctrl+Z** (одно действие
   истории).

В сводке панели: сколько ролей LLM поставил уверенно, сколько спорных, какая
модель отвечала и за какое время. Если таблица мусорная, LLM может ответить
«нечего размечать» — роли не меняются, в панели останется его пояснение.

## Спорные клетки и как их править

Клетки, где LLM не уверен (confidence < 0.7), подсвечиваются **жёлтой рамкой** и
собираются в список панели: «r6 c2 «текст» — значение 55% (альт.: параметр 40%)».

- **Клик по пункту** — клетка выделяется на канвасе; дальше штатные кнопки ролей.
- **Чип альтернативы** («→ Параметр 40%») под пунктом — сменить роль одним кликом
  (подставятся и название/единица из предложения LLM).
- **«✓ верно»** — согласиться без правки: рамка снимется, пункт станет проверенным.
- Список **не сбрасывается** от правок: исправленный пункт помечается
  «✏️ исправлено», в сводке виден прогресс «проверено X/N». Полный сброс — при
  структурных правках, смене таблицы или возврате к полностью своим ролям.

Каждое ваше исправление (что предложил LLM → что выбрали вы) автоматически
пишется в журнал на сервере. Журнал идёт в метрику точности
(`GET /api/llm/metrics`) и в тюнинг промптов.

## Кэш и стоимость

- Ответ **кэшируется**: повторное предложение той же таблицы (те же промпты,
  тот же контекст) приходит мгновенно и бесплатно — в сводке будет «📦 из кэша».
- После правки промптов на сервере кэш обновляется автоматически.
- Бюджет запроса ~3.5k токенов ≈ **до 2₽ за таблицу**; кэш делает повторные
  предложения бесплатными. Настройка кэша (200 последних ответов) — серверная,
  от вас ничего не требуется.
- Хотите свежий ответ после правки промптов — нажмите кнопку ещё раз с флагом
  обновления на стороне API (`refresh: true`); из UI обычный клик отдаёт кэш,
  если ответ уже есть.

## Ограничения и известные проблемы

- **Не работает при структурных правках таблицы** — координаты предложения
  по исходной сетке (см. выше).
- Требует настроенного ключа; при недоступности облачного API кнопка вернёт
  ошибку 502 (все модели не ответили) — таблица и ваши роли не пострадают.
- LLM размечает по структуре: если детектор нашёл таблицу плохо (разрезал,
  потерял строки), сначала исправьте структуру правками — но учтите, что после
  правок LLM-кнопка заблокирована; в этом случае размечайте вручную или
  предложите маппинг на исходной структуре и поправьте результат.
- Точность на эталонном наборе измеряется отдельным закрытым прогоном
  (в публичную версию не входит); целевая — >85%. Живые метрики
  вашего стенда — `GET /api/llm/metrics`.
