# Контракт стенда «Техническая документация»

Внутренний контракт для тестового сервиса. Результат извлечения спроектирован так,
чтобы его можно было встроить во внешний сервис: параметры + evidence + стадии обработки.

## Форматы документов

| Формат | Загрузчик | Детали |
|---|---|---|
| PDF | PyMuPDF (текстовый слой) | двухдетекторная детекция таблиц (слова + векторная сетка), см. [TABLE_DETECTION.md](./TABLE_DETECTION.md) |
| PDF (скан) | OCR-воркер PaddleOCR (HTTP) | распознавание постранично, слова с координатами |
| XLSX / XLS | openpyxl | каждый непустой лист — таблица |
| DOCX | python-docx | таблицы документа + абзацы (key:value) |
| CSV | csv (автодетект разделителя/кодировки) | одна таблица |
| TXT | строки текста | режим «Метка: значение» |

Разбор документов кэшируется (`load_document_cached`): LRU на 8 документов,
ключ — путь + формат + mtime + размер; повторные запросы (extract после upload)
не парсят файл заново, изменение файла сбрасывает кэш автоматически.

## Модель таблиц (PDF)

Таблица (`Table`) несёт метаинформацию о структуре (полная модель —
[TABLE_DETECTION.md](./TABLE_DETECTION.md)):

- `source` — источник детекции: `"word"` (раскладка слов) / `"grid"`
  (нарисованная сетка; видит merged cells и транспонированные матрицы);
- `header_rows` — число строк шапки (0 = не определено), многострочные шапки
  поддерживаются;
- merged cells: якорь с `rowspan`/`colspan` + клетки-продолжения
  (`is_merged`, `merged_with`); чтение — только через `Table.get_cell(row, col)`;
- `is_matrix` + `orientation` (`"rows"` — модели в первой колонке,
  `"columns"` — модели в шапке).

Обратная совместимость: плоский доступ `table.rows[i][j]` сохранён, все поля
метаинформации сериализуются в `to_dict()` / восстанавливаются `from_dict()`.

## Модель «набора» (пресета)

Набор — JSON-конфиг маппинга, аналог `parse_rule` внешней системы, но под паспорта/ТХ:

```json
{
  "id": "passport_pump_2col",
  "name": "Паспорт насоса (метка → значение)",
  "doc_type": "passport",
  "columns": {
    "count": 2,
    "has_header": false,
    "roles": {"label": 0, "value": 1},
    "header": {"наименование": "label", "значение": "value", "ед. изм.": "unit"}
  },
  "labels": ["подача", "напор", "мощность"],
  "section_keywords": ["технические характеристики"],
  "header_keywords": ["наименование", "значение"],
  "units": ["м3/ч", "кВт", "об/мин"],
  "include_all": false,
  "keyvalue": false,
  "fingerprint": null
}
```

Роли колонок: `label` (метка/атрибут), `value` (значение), `unit` (единица),
`section` (заголовок секции), `ignore`.

### Фингерпринт и подбор набора

- **Точный**: sha256 от (загрузчик, число колонок, нормализованные заголовки шапок).
- **Частичный**: Jaccard по множествам заголовков и меток (порог 0.45), вес колонок.
- Фингерпринт считается только по структуре, не по данным (как в Фазе 2).
- При сохранении набора «из успешного извлечения» фиксируется точный фингерпринт —
  следующий такой же документ подхватывается автоматически.

## Результат извлечения

```json
{
  "name": "Подача",
  "value": "12,5",
  "unit": "м3/ч",
  "source": "preset | llm",
  "verified": true,
  "evidence": {
    "document": "паспорт.pdf",
    "page": 2,
    "quote": "Подача: 12,5 м3/ч",
    "table": "p2-t1",
    "row": 4
  }
}
```

- `evidence` повторяет модель внешней системы (`документ/страница/цитата`).
- Параметр считается `verified=true` только если значение взято из реально
  найденной цитаты (детерминированный контур — из ячейки таблицы; LLM-контур —
  цитата проверяется по нормализованному тексту фрагмента).
- Стадии обработки (совместимы с `certificates`): `PARSED` → извлечение →
  `COMPLETED`; для сканов добавляется `OCR_COMPLETED` (в этой версии — синхронно).

## LLM-контур

- Провайдер: OpenAI-совместимый эндпоинт (YandexGPT по умолчанию).
- На вход LLM уходят только фрагменты (таблицы/строки) с id — не весь документ.
- Если в `POST /extract` передан `preset_id` — словарь меток набора уходит в промпт
  как подсказка (не ограничение), а фрагмент таблицы `table_id`/авто-таблицы ставится
  первым в списке фрагментов.
- Ответ: `{"parameters":[{"name","value","unit","fragment_id","quote"}]}`.
- Приём результата только при условии: `quote` найдена во фрагменте после
  Unicode-нормализации; `name` и `value` непустые.
- Пустой прогон не затирает предыдущий непустой результат — в ответе возвращается
  прошлый результат, а в `warnings` добавляется пояснение.
- Модели перебираются по порядку: основная, затем фолбэки из `YANDEXGPT_RULE_MODELS`.
- При пустом ключе LLM выключен — сервис работает детерминированно, в облако ничего не уходит.

## LLM-ассистент маппинга

- `POST /api/llm/suggest-mapping` (`document_id`, `table_id`, `context?`) — предложить
  аннотации ролей для таблицы документа. Ответ: `{orientation, structure, complexity,
  annotations[], notes, summary, model, processing_time_ms}`.
- Аннотации в ответе — **развёрнутые по якорям** и провалидированные против сетки
  исходной таблицы: LLM отвечает компактно (`row`/`col` либо `range: [r0, c0, r1, c1]` —
  роль получают блоки, якорь которых в прямоугольнике), сервер разворачивает range-зоны
  в по-якорные аннотации (`expand_range`), координаты клампятся/проверяются по границам
  сетки, точечные аннотации нормализуются к якорям merged (`get_cell`) и побеждают
  развёрнутые при конфликте; роли — те же 7, что в Visual Mapper. `label` — нормализованное
  название, `unit` — единица (обычно вынесена из названия параметра), `confidence` 0..1
  и `alternatives` для спорных клеток. `orientation`/`structure`/`complexity` —
  нормализованные enum (мусор → null). Ответ, где все аннотации вне сетки, считается
  невалидным → фолбэк на следующую модель. Применение предложения — только вручную
  через Visual Mapper (кнопка «🤖 Предложить маппинг»: аннотации применяются
  через `setAnnotations` одним действием истории, спорные клетки confidence < 0.7
  подсвечиваются отдельным слоем и перечисляются в панели с альтернативами),
  автоприменения нет.
- Промпты — `backend/app/prompts/` (system + 3 user-шаблона + few-shot примеры (синтетические)),
  контракт и правила правки — в `backend/app/prompts/README.md`.
- Вызов LLM — общий с контуром извлечения (`chat_completions`): перебор моделей
  с фолбэками, режим JSON по `LLM_JSON_MODE`; для маппинга — temperature 0.1,
  max_tokens 4000, один few-shot пример по типу таблицы (~3.5k токенов на запрос).
- Кэш (4.7): ответ кэшируется по sha256-фингерпринту **сообщений целиком**
  (`messages_fingerprint` — таблица + контекст + промпты) в
  `data/llm_suggest_cache.json` (200 последних записей). Повторное предложение
  той же таблицы не ходит в облако: `cached: true`, `processing_time_ms: 0`.
  Правка промптов (`app/prompts/`) автоматически инвалидирует кэш — ключ
  меняется вместе с system/user-шаблонами. `refresh: true` в запросе —
  принудительный обход кэша.
- `GET /api/llm/metrics` — метрики (4.7): счётчики запросов/кэш-хитов/отказов,
  суммарное время и токены (usage ответа LLM) из `data/llm_stats.json`;
  производные `cache_hit_rate`/`avg_time_ms`; точность — по журналу
  `llm_feedback.jsonl` (`accuracy` = доля клеток, где пользователь подтвердил
  роль LLM; дублей по клетке нет — берётся последняя коррекция; `null`, если
  коррекций ещё не было).
- Ошибки: 404 документ/таблица, 503 `LLM_NOT_CONFIGURED` (нет ключа),
  502 `LLM_FAILED` (все модели не ответили валидным JSON).
- `POST /api/llm/feedback` (`document_id`, `table_id`, `model?`,
  `corrections[]`) — журнал коррекций пользователя: для каждой клетки
  `row/col`, текст, `llm_role`+`llm_confidence`+`alternatives` (что предложил
  LLM) и `user_role`+`via` (что выбрал пользователь: `alternative` — чип
  альтернативы в панели спорных, `role-button` — кнопка роли, `confirm` —
  «✓ верно»). Записи дополняются `timestamp` и дописываются в
  `data/llm_feedback.jsonl` (по строке на коррекцию); UI шлёт fire-and-forget,
  сбой записи не мешает работе. Роли валидируются (те же 7); пустой список →
  422 `NO_CORRECTIONS`, неверная роль → 422 `INVALID_ROLE`. Существование
  документа не проверяется — журнал независим от жизненного цикла документов.
  Анализ журнала — материал для тюнинга промптов (этап 4.8).

## Шаблоны маппинга (Visual Mapper)

Маппинг из Visual Mapper — отдельная сущность от наборов: **аннотации ролей в
финальных координатах** (после структурных правок) + **ops-рецепт правок**
(`merge`/`split`/`transpose`/`del_rows`/`del_cols` со слотами исходной сетки).
Итоговую таблицу шаблон не хранит — у похожей таблицы другие тексты; рецепт
координатных операций воспроизводит правки на идентичной структуре.

Подбор: сигнатура таблицы `{cols, headers}` (нормализованные тексты шапки);
матч — «exact» по sha256-фингерпринту или «partial» при равном `cols` и
Jaccard шапки ≥ 0.75. Хранение: `data/mappings/*.json`, отдельно от наборов.

Семантика привязки значение → параметр/модель/единица/секция реализована
дважды с паритетом, закреплённым тестами на синтетических таблицах: клиент (`preview.js`,
мгновенный отклик/фолбэк) и сервер (`app/mapping_apply.py` — `build_preview`,
`apply_ops`, `normalize_annotations`).

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/documents` | загрузка документа (multipart: `file`, `ocr`) |
| GET | `/api/documents` | список |
| GET | `/api/documents/{id}` | карточка + таблицы + последний результат |
| GET | `/api/documents/{id}/page/{n}` | PNG страницы (PDF) |
| GET | `/api/documents/{id}/pageinfo/{n}` | размеры страницы для оверлея |
| POST | `/api/documents/{id}/extract` | извлечение (`preset_id`, `table_id`, `use_llm`, `include_all`) |
| POST | `/api/documents/{id}/reprocess` | повторное извлечение |
| GET/POST/PUT/DELETE | `/api/presets` | CRUD наборов |
| POST | `/api/presets/from-extraction` | сохранить набор из успешного прогона (`document_id`, `name?`, `preset_id?`, `table_id?`) |
| POST | `/api/presets/save-from-mapping` | сохранить шаблон из Visual Mapper (`name`, `document_id`, `table_id`, `ops`, `annotations`) |
| GET | `/api/mapping/templates` | список шаблонов маппинга |
| DELETE | `/api/mapping/templates/{id}` | удалить шаблон |
| GET | `/api/mapping/match` | лучший шаблон для таблицы (`document_id`, `table_id`) — полный или `null` |

| POST | `/api/mapping/validate` | предпросмотр извлечения по ops+ролям → `{cards, stats, warnings}` |
| POST | `/api/mapping/apply-template` | применить шаблон к таблице → правленая таблица + нормализованные роли (+`skipped_annotations`) |
| POST | `/api/llm/suggest-mapping` | предложить маппинг таблицы через LLM (аннотации с confidence, без автоприменения; `refresh?` — обойти кэш) |
| POST | `/api/llm/feedback` | записать коррекции пользователя «LLM предложил → выбрал» в журнал (тюнинг промптов) |
| GET | `/api/llm/metrics` | метрики LLM-маппинга: запросы/кэш/токены/время + точность по журналу коррекций |
| GET | `/api/health` | статус |

## Интеграционные швы

- Ядро (загрузчики + детекция + извлечение) может быть встроено во внешний
  сервис как нативный extraction-контур; `parameters`+`evidence` — без изменений.
- Страница стенда переносится во frontend внешней системы (экран `/certificates`).
- Наборы маппятся в модель правил внешней системы (аналог `parse_rules`).
- OCR: HTTP-протокол совпадает с `PADDLEOCR_BASE_URL` внешней системы (multipart PDF → слова).
