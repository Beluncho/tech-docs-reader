# Детекция таблиц (Этап 2)

Модель данных и алгоритмы детекции таблиц в PDF. Код: `backend/app/detect.py`,
`backend/app/loaders/pdf_loader.py`. План этапа:
[02-TABLE-DETECTION.md](./implementation-plan/02-TABLE-DETECTION.md).

## Обзор

Детекция двухдетекторная, результаты консервативно сливаются:

```
страница PDF
  ├─ get_text("words")          → word-boxes (текст + координаты)
  ├─ get_drawings()             → векторные линии (рамки ячеек)
  ├─ detect_tables_on_page      → таблицы по раскладке слов      (source="word")
  ├─ detect_tables_from_grid    → таблицы по нарисованной сетке  (source="grid")
  └─ merge_page_tables          → слияние + аннотация (шапка, матрица)
```

- **Word-детектор** работает всегда, где есть текстовый слой (или слова OCR):
  группирует слова в строки, разбивает на ячейки по горизонтальным разрывам,
  строит колонки кластерами сепараторов. Merged cells не видит — режет
  объединённые ячейки на куски.
- **Grid-детектор** работает там, где ячейки нарисованы линиями (типично для
  каталожных таблиц ТХ): строит сетку из векторных линий, находит merged cells
  по отсутствующим внутренним границам. Бесполезен без разлиновки.
- **Слияние** оставляет grid-таблицу, только если она несёт контент,
  недоступный word-детектору (merged cells или транспонированная матрица);
  word-кусочки, покрытые оставшейся сеткой, отбрасываются.

## Модель данных

`backend/app/preset.py`: `Cell` и `Table` (dataclass, round-trip `to_dict` /
`from_dict` для JSON в meta документа).

### Cell

| Поле | Тип | Описание |
|---|---|---|
| `text` | `str` | текст ячейки (склейка слов по порядку чтения) |
| `row`, `col` | `int` | позиция в сетке таблицы (0-based) |
| `page` | `int \| None` | номер страницы (0-based) |
| `x0..y1` | `float \| None` | bbox в пунктах PDF (word-детектор ставит координаты только непустым ячейкам) |
| `rowspan`, `colspan` | `int` | размер объединения (у якоря > 1, у обычной ячейки 1) |
| `is_merged` | `bool` | True у клетки-продолжения |
| `merged_with` | `(row, col) \| None` | ссылка на якорь (только у продолжений) |

### Контракт merged cells

- **Якорь** — ячейка с `rowspan>1` или `colspan>1`; её `text` содержит весь
  текст объединения, её bbox покрывает весь диапазон rowspan×colspan.
- **Продолжение** — ячейка с `is_merged=True` и `merged_with=(row, col)` якоря;
  текст пустой, координаты — занимаемая позиция сетки.
- Никогда не читайте `rows[i][j]` напрямую для обхода объединений — используйте
  `Table.get_cell(i, j)`: он раскрывает продолжение в якорь (с защитой от
  циклических ссылок).

### Table

| Поле | Тип | Описание |
|---|---|---|
| `id` | `str` | `p{страница+1}-t{номер}` — стабилен в пределах страницы |
| `rows` | `list[list[Cell]]` | полная сетка строка×колонка (включая продолжения) |
| `bbox` | `[x0, y0, x1, y1]` | границы таблицы в пунктах PDF |
| `source` | `str \| None` | `"word"` / `"grid"` / `None` (другие загрузчики) |
| `header_rows` | `int` | строк заголовка (0 = шапки нет) |
| `has_merged_cells` | `bool` | есть ли rowspan/colspan |
| `is_matrix`, `orientation` | `bool`, `str \| None` | матрица модель×параметр; `"rows"` — модели в первой колонке (НС, СМ, ЭЦВ), `"columns"` — модели в шапке (VP, 1Кс) |
| `grid_rows`, `grid_cols` | `int` | размер сетки |

Методы: `get_cell(row, col)` (с раскрытием merged), `iter_data_rows()`
(строки после шапки), `n_cols`, `has_header`, `to_dict()` / `from_dict()`.

## Алгоритмы

### Word-детектор (`detect_tables_on_page`)

1. Слова группируются в строки по пересечению вертикальных интервалов
   (`_group_lines`), строка сортируется по x.
2. Строка режется на ячейки по разрывам между словами (порог от медианной
   высоты слова).
3. Середины разрывов кластеризуются в границы колонок; ячейки назначаются
   колонкам по максимальному перекрытию.
4. Колонки, встречающиеся меньше чем в 2 строках, отбрасываются (шум).
5. Смежные строки с ≥2 непустыми ячейками образуют блоки; блоки ≥3 строк —
   таблицы (с захватом близких текстовых строк-подписей).

Ограничение: merged cells не видны — объединённая ячейка выглядит как пустые
соседи и разрывы. Такие таблицы ловит grid-детектор.

### Grid-детектор (`detect_tables_from_grid`)

1. Тонкие нарисованные прямоугольники/линии разбиваются на вертикальные и
   горизонтальные сегменты; координаты кластеризуются в линии сетки
   (с фильтрацией по числу поддерживающих сегментов и склейкой удвоенных рамок).
2. Полосы между соседними горизонтальными линиями; вертикальные линии,
   пересекающие полосу, дают колонки. Полосы с ≥2 колонками образуют таблицу.
3. **Merged cells**: полная сетка полос×колонок достраивается границами —
   между соседними ячейками, где внутренняя линия НЕ нарисована, граница
   отсутствует. Связные области ячеек без границ (flood fill) — кандидаты
   на объединение; прямоугольные области >1 ячейки становятся merged cell
   (якорь + продолжения), L-образные остаются раздельными ячейками.
4. Слова биннятся центром в ячейки сетки (двоичный поиск по границам).
5. Разреженные сетки отсеиваются: таблица остаётся, если ≥2 строк с ≥2
   непустыми ячейками; фоновая разлиновка анкет режется плотностью
   (`GRID_MERGE_DENSITY = 0.15`) на этапе слияния.

### Слияние (`merge_page_tables`)

Grid-таблица попадает в результат, только если она **не дублирует** словесную
(bbox не покрыт более чем на 50% word-таблицей) **и** несёт недоступный
word-детектору контент:

- транспонированная матрица (модели в шапке, ≥3 ячеек-кодов моделей), или
- merged cells при плотности заполнения ≥ `GRID_MERGE_DENSITY` (0.15).

Word-кусочки, покрытые более чем на 50% оставшейся grid-таблицей, отбрасываются
— сетка собирает их точнее. Затем всем таблицам страницы присваиваются
финальные id `p{n}-t{k}` и запускается аннотация.

### Аннотация (`annotate_table`)

Матричная структура (`detect_matrix_structure`) считается **один раз** и
переиспользуется обоими определителями:

- **`is_matrix` / `orientation`**: «rows» — ≥3 строк с моделью в первой колонке
  (дефисные коды с цифрами: `СМ80-50-200-2`, `НС 13-70`), ≥2 колонки значений,
  шапка с названиями параметров над телом (или merged-шапка); перечни деталей
  («Кол. шт», «Масса 1») отсеиваются. «columns» — ≥3 ячеек моделей в одной из
  первых строк, ниже строки «параметр + значения».
- **`header_rows`**: граница «шапка → данные» — последняя строка-заголовок перед
  первой строкой данных (≥2 значений или модель в первой колонке). Подписи
  «Таблица 1» / «Продолжение табл. 2» шапкой не считаются, но и не разрывают
  её. Многострочные шапки поддерживаются (СМ p9: 2 строки).

## Использование

```python
from app.loaders import load_document

lr = load_document("СМ (2).pdf", "pdf")
for t in lr.tables:
    print(t.id, t.source, f"{t.grid_rows}x{t.grid_cols}",
          "matrix" if t.is_matrix else "", t.orientation or "")

t = next(t for t in lr.tables if t.id == "p9-t2")

# строки данных без шапки
for row in t.iter_data_rows():
    ...

# ячейка с раскрытием merged (клетка-продолжение вернёт якорь)
cell = t.get_cell(1, 2)          # rowspan=18: «0,0036 (13)»
anchor = t.get_cell(5, 2)
assert cell is anchor

# сериализация (сохраняется вся метаинформация)
d = t.to_dict()
t2 = Table.from_dict(d)
```

Кэш (повторные запросы не парсят документ заново):

```python
from app.loaders import load_document_cached

lr = load_document_cached("СМ (2).pdf", "pdf")   # LRU-8, ключ путь+mtime+размер
```

## Производительность (подэтап 2.9)

Замеры `scripts/benchmark_detection.py` (Python 3.12, локальная машина):

| Документ | Страниц | Таблиц | Время | Пик памяти |
|---|---|---|---|---|
| НС 13-38-60 | 43 | 41 | ~0.7 с | 3 MB |
| СМ (2) | 59 | 66 | ~2.2-2.5 с | 19 MB |
| VP-L | 21 | 21 | ~0.4 с | 2 MB |

Цель этапа (<10 с на 50 стр. / 200 табл., <500 MB) выполняется с запасом.
Горячие места устранены: bisect в `_nearest_line` и биннинге слов, бакетинг
горизонтальных сегментов по линиям сетки с кэшем перекрытий для `hborder`.
Остаточный hotspot — `page.get_drawings()` внутри PyMuPDF.

`load_document_cached` (`app/loaders/__init__.py`): LRU на 8 документов,
ключ `(путь, формат, mtime_ns, размер)` — изменение файла сбрасывает кэш
автоматически; запросы с `ocr_words` не кэшируются. Upload и extract в API
используют его (extract после upload берёт разбор из кэша).
