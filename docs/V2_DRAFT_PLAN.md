# Tech Docs Reader v2: наметки

Черновик к следующей версии. Не обязательство, а возможный подход к развитию;
дописывается по ходу. Статусы: **✔ принято** · **◐ предварительно** · **? открыто**.

## 1. Направления

| # | Направление | Статус |
|---|---|---|
| Н1 | TDR встраивается в более крупную систему **модулем или микросервисом**; UI стенда остаётся инструментом разработки и проверки | ◐ |
| Н2 | **В LLM не отправляем документ целиком.** Только минимальный фрагмент, достаточный, чтобы модель вернула *правило* (роли ячеек, структуру), а не значения. Значения извлекает код по правилу | ✔ |
| Н3 | Модель не фиксируем: работаем через OpenAI-совместимый шлюз/прокси. Смена модели — конфигурация, не архитектура | ◐ |
| Н4 | Выход TDR — **факты с доказательствами** (evidence до ячейки) для внешнего движка оценки/сопоставления | ◐ |

## 2. Пайплайн

```
документ ─► разбор (текст, разделы, таблицы)
         ─► есть пресет/шаблон? ──да──► извлечение кодом ─────────────┐
                    │ нет                                              │
                    ▼                                                  │
              LLM: фрагмент → правило (роли ячеек / структура)         │
                    ▼                                                  │
              проверка правила кодом (сетка, цитаты)                   │
                    ▼                                                  │
              экран проверки: человек правит, сохраняет правило ───────┤
                                                                       ▼
                                                  факты + evidence ─► потребитель
```

Принципы:
- **LLM — только для новых структур.** Каждое сохранённое правило уменьшает
  число вызовов. Метрика: доля таблиц, обработанных без LLM.
- **Что уходит в модель (уже так в v1):** одна таблица, ≤ 40 строк (голова +
  хвост), ячейка ≤ 60 символов, сведения об объединениях и шапке. Ответ
  валидируется по сетке и кэшируется. Размер запроса не зависит от размера
  документа.
- **Текст вне таблиц** (требования в абзацах): тоже по фрагментам — раздел или
  пункт, а не документ. ? Формат запроса и ответа — проработать.
- **Два вида правил, не путать:**
  - *правило извлечения* — шаблон/пресет: как читать документ (это TDR);
  - *правило оценки* — как проверять соответствие (это потребитель фактов).

## 3. Черновик контракта факта

| Поле | Есть в v1 | Нужно для v2 |
|---|---|---|
| `name`, `value`, `unit` | ✔ | ✔ |
| `value_type`: exact / range / boolean / enum | — | ✔ |
| `context`: модель, позиция, раздел | — | ✔ |
| статус: READY / MISSING / CONFLICT | — | ✔ |
| `evidence`: `document_id`, `page`, `quote`, `table`, `row`, `col`, `source` | без `col`; `source` = preset/llm | ✔ (трасса до ячейки) |
| `confidence`, `verified` | частично | ? |

## 4. Экран проверки

Через него проходит каждый документ без готового правила: слева факты, справа
источник с подсветкой; Visual Mapper открывается внутри как инструмент правки.
После правки правило сохраняется и в следующий раз применяется без LLM.
