# План доработки многостраничных таблиц по итогам код-ревью

## Контекст

В рабочей копии (незакоммиченные изменения) появилась поддержка многостраничных
таблиц в Visual Mapper: к основной таблице можно подключить фрагменты-продолжения
с последующих страниц, а в шаблоне они сохраняются как относительные ссылки
(`MappingContinuationRef`). Ревью нашло 6 проблем: 2 важные и 4 мелкие.
Цель доработки — продолжения не должны приклеиваться к чужим таблицам и терять
строки, состояние UI не должно перемешиваться, а разметка не должна пропадать
при переключении фрагментов.

Решения, принятые пользователем:
- **№2:** поиск продолжения с проверкой по сигнатуре; неподтверждённые кандидаты
  пропускаются с предупреждением.
- **№3:** отбрасываются только те строки фрагмента, которые совпадают с шапкой
  основной таблицы; флаг `skip_header_rows` включает или выключает это для
  каждого фрагмента (так же закрывается №5).

Какие файлы затронуты: `backend/app/mapping_apply.py`, `backend/app/api/routes.py`,
`backend/app/models.py`, `frontend/app.js`, `docs/CONTRACT.md`,
`docs/VISUAL_MAPPER.md`, `tests/test_mapping_validate.py`.

## [x] Этап 2. №3 + №5: распознавание повторной шапки (backend)

`backend/app/mapping_apply.py`.
- Новая функция `repeated_header_rows(primary: Table, fragment: Table) -> int`.
  Для `i < primary.header_rows` сравнивает построчно: нормализованные тексты
  колонок строки `fragment.rows[i]` должны совпасть с `primary.rows[i]`.
  Нормализация через `normalize_header` из `backend/app/normalize.py`, как в
  `mapping_template.table_signature`. Пустые строки не считаются совпадением.
  Сравнение прекращается на первом несовпадении. Если у основной таблицы
  `header_rows == 0`, функция возвращает 0.
- `combine_continuation_tables(table, continuations, *, skip_header_rows=True)`:
  параметр может быть `bool` или `list[bool]` (флаг для каждого фрагмента).
  Число отбрасываемых строк считается как `repeated_header_rows(primary_snapshot, fragment)`,
  если флаг включён, и 0, если выключен. `primary_snapshot` — шапка основной
  таблицы, снятая **до** добавления строк. Логика перепривязки
  `merged_with` и `is_merged` остаётся прежней.
- `routes.py`:
  - `_selected_continuations` пишет в ссылку `skip_header_rows: True` и новое поле
    `repeats_header: repeated_header_rows(table, fragment) > 0`.
  - `apply_mapping_template` передаёт флаги `skip_header_rows` из ссылок
    (§3 возвращает их вместе с таблицами).
- `models.py`: в `MappingContinuationRef` добавить `repeats_header: bool | None = None`.

## [x] Этап 3. №2 + №6: строгий поиск продолжений шаблона (backend)

`_resolve_template_continuations` в `routes.py` ≈565–590. Функция возвращает
`list[tuple[Table, dict]]` (фрагмент и его ссылку) и `warnings: list[str]`.
- `table_index` считается по **всем** таблицам страницы, как при сохранении.
- Кандидат подходит (`_continuation_confirmed`), только если выполнены условия:
  1. `n_cols` совпадает; кандидат не основная таблица и ещё не использован;
  2. если `ref.repeats_header`, то `repeated_header_rows(table, cand) > 0`;
  3. если повторной шапки нет: у кандидата нет собственной шапки, отличной от
     шапки основной (`cand.header_rows == 0` или шапка совпадает), **и** он идёт
     первым на своей странице, **и** предыдущая часть (основная таблица или
     прошлый фрагмент) идёт последней на своей странице.
- Порядок поиска: сначала таблица по `table_index`, затем остальные таблицы
  страницы в исходном порядке, к которым применяются те же проверки.
  Слепого «первая подходящая по числу колонок» больше нет.
- Неподтверждённая ссылка пропускается, в `warnings` добавляется
  «Продолжение на стр. +N не подтверждено — пропущено».
- `models.py`: в `MappingApplyOut` добавить `warnings: list[str] = []` и
  заполнять его в `apply_mapping_template`.
- Ссылки без `repeats_header` (`None`, старый формат) проверяются по правилу 3.
