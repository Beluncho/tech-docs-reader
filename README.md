# Tech Docs Reader

Сервис для извлечения технических характеристик из документов: паспортов
оборудования, сертификатов, опросных листов и технических заданий. На вход —
PDF, XLSX, DOCX, CSV или TXT; на выходе — параметры со значением, единицей и
**evidence**: страницей и цитатой, откуда взято значение.

Сервис сочетает три контура:

- **детерминированный** — загрузчик, детекция таблиц, наборы правил (пресеты);
- **визуальный** — Visual Mapper на Fabric.js: разметка ролей ячеек вручную;
- **LLM** — извлечение и предложение маппинга через YandexGPT (опционально).

## Архитектура

```
┌──────────────┐      HTTP      ┌───────────────────────────┐
│  frontend    │ ─────────────▶ │  backend (FastAPI)        │
│  vanilla JS  │                │  loaders → detect →       │
│  Fabric.js   │ ◀───────────── │  extract / mapping / LLM  │
└──────────────┘                └─────────────┬─────────────┘
                                              │ HTTP (optional)
                                    ┌─────────▼─────────┐
                                    │  ocr-worker       │
                                    │  PaddleOCR        │
                                    └───────────────────┘
```

- `backend/app/loaders/` — PDF (PyMuPDF), XLSX, DOCX, CSV, TXT;
- `backend/app/detect.py`, `matrix.py` — детекция таблиц и матриц «модель × параметр»;
- `backend/app/extract.py`, `preset.py` — извлечение по наборам;
- `backend/app/mapping_apply.py`, `mapping_template.py` — серверный паритет Visual Mapper;
- `backend/app/llm.py`, `llm_mapping.py` — LLM-контуры;
- `backend/app/prompts/` — системный промпт, шаблоны и few-shot примеры;
- `frontend/` — одна страница: загрузка, предпросмотр, параметры, Visual Mapper;
- `ocr-worker/` — PaddleOCR как отдельный HTTP-сервис (Docker profile `ocr`).

## Быстрый старт (Docker)

```bash
cp .env.example .env        # ключи LLM — при необходимости
docker compose up -d --build

# OCR-воркер нужен только для сканов
docker compose --profile ocr up -d --build

# открыть http://localhost:8081
```

Порт UI меняется через `UI_PORT` (по умолчанию `8081`). Наружу публикуется только
`ui`; `api` и `ocr` доступны во внутренней сети. Данные — в именованном volume
`tech-docs-data`; внешняя БД не нужна.

## Запуск без Docker

```bash
cd backend
python -m venv .venv && .venv\Scripts\activate   # Windows
pip install -r requirements.txt

set PYTHONPATH=%CD%
set DATA_DIR=..\data
uvicorn app.main:app --reload --port 8000
```

Фронтенд отдаётся самим API: http://localhost:8000/ui/.

## Настройка LLM

```dotenv
LLM_PROVIDER=yandexgpt
YANDEXGPT_API_KEY=...
YANDEXGPT_FOLDER_ID=...
YANDEXGPT_API_BASE_URL=https://ai.api.cloud.yandex.net/v1
YANDEXGPT_RULE_MODEL=qwen3-235b-a22b-fp8/latest
YANDEXGPT_RULE_MODELS=qwen3-235b-a22b-fp8/latest,qwen3.6-35b-a3b/latest,deepseek-v4-flash/latest,yandexgpt-5.1/latest
```

- Модели перебираются по порядку: основная, затем фолбэки.
- Основная модель должна поддерживать JSON и не быть «рассуждающей»: иначе ответ
  упирается в таймаут.
- Без ключа кнопки LLM возвращают понятную ошибку, а детерминированный контур
  продолжает работать полностью локально.

## OCR

Сканированные PDF обрабатываются OCR-воркером (PaddleOCR, профиль `ocr`).
API обращается к нему по `OCR_SERVICE_URL` (в compose — `http://ocr:8300`).
Без воркера загрузка с флагом OCR вернёт `OCR_FAILED`; PDF с текстовым слоем
работают и без него.

## Как пользоваться

1. **Загрузка** — drag&drop или выбор файла: `pdf`, `xlsx`, `xls`, `docx`, `csv`,
   `txt`. Для сканов — чекбокс «распознать сканы».
2. **Извлечение** — выбрать набор (или автоподбор по фингерпринту) → «Извлечь».
   У каждого параметра: значение, единица, источник (`набор` / `LLM`), страница
   и цитата. Для PDF превью страницы кликабельно, найденные таблицы обведены.
3. **Настройка набора** — «Настроить набор»: выбрать таблицу, назначить роли
   колонкам (метка / значение / единица / секция / игнор), поправить словарь
   меток, сохранить. Удачный прогон можно превратить в набор кнопкой
   «Сохранить правило из результата».
4. **LLM-извлечение** — «Извлечь через LLM», если детерминированный контур не
   справился. Цитаты проверяются кодом; параметр без подтверждённой цитаты
   отбрасывается.
5. **Visual Mapper** — «🎨 Визуальный маппинг»: разметка ролей ячеек на canvas,
   объединение/разделение, транспонирование, шаблоны, предпросмотр и экспорт.
   Кнопка «🤖 Предложить маппинг» размечает сложную таблицу черновиком.

## Стартовые наборы

| Набор | Для чего |
|---|---|
| `passport_pump_2col` | паспорт насоса, схема «метка → значение» |
| `passport_table_header` | таблица «показатель / ед. / значение» |
| `certificate_2col` | сертификаты и декларации соответствия |
| `tz_table` | таблицы ТЗ и опросных листов |
| `keyvalue_generic` | строки «Метка: значение» |
| `generic_2col_all` | любые пары «метка → значение» без словаря |
| `pump_main` | паспорт/РЭ насоса: все пары + матрицы «модели × параметры» |

Пользовательские наборы сохраняются в `data/presets/*.json` (volume) и переживают
перезапуск.

## Что демонстрирует

- детекцию таблиц по сетке и словам страницы, включая merged-ячейки и rowspan;
- матрицы «модель × параметр» в обеих ориентациях;
- evidence для каждого параметра и отбрасывание неподтверждённых LLM-значений;
- визуальный маппинг таблиц с шаблонами и предпросмотром;
- LLM-ассистента разметки с кэшем и журналом коррекций (`/api/llm/metrics`);
- тесты на pytest: API, загрузчики, детекция, извлечение, маппинг, LLM (с моками).

## Метрики

Замеры на закрытом наборе из 43 документов (33 PDF), без OCR:

| Операция | Результат |
|---|---|
| Загрузка без OCR, медиана | 173 мс |
| Загрузка без OCR, 90-й перцентиль | 826 мс |
| Детекция таблиц, 50 страниц | 2.28 с |
| Извлечение с набором, максимум на опорных | 664 мс |
| Документов с найденными параметрами | 30 из 43 |
| Максимум параметров в одном документе | 1017 |

Числа — серверная стоимость операций (TestClient, CPython 3.12, без сети и
браузера). Живые метрики LLM на стенде — `GET /api/llm/metrics`.

## Тесты

```bash
pip install -r backend/requirements-dev.txt   # зависимости API + pytest
python -m pytest tests -q
# 198 passed
```

Публичная версия не содержит тестов и скриптов, которым нужен закрытый набор
документов. Остальные тесты работают на синтетических таблицах и не требуют
внешних данных.

## Ограничения

- Матрицы паспортов насосов разбираются детерминированно; экзотические вёрстки
  других поставщиков — вручную или через LLM.
- Распознавание колонок — по раскладке, без ML; сложные шапки требуют маппинга.
- LLM-контур не сохраняет правило сам: после удачного прогона нажмите
  «Сохранить правило из результата».
- OCR работает только через воркер (в compose — профиль `ocr`).
